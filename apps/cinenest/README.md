# CineNest — TapeNest online cinema mini app

Skeleton from stage 1 (2026-09-25). It uses the same stack and conventions as
[WavePlayer](../waveplayer/README.md). Auth is real, through api-gateway.
The cinema domain runs on MSW mocks until streaming-service arrives in stage 4
(until then the gateway answers `501` for `/api/v1/cinema/*`).

**Stack:** React 18.3 · TypeScript 5.6 (strict) · Vite 5 · TanStack Query 5 · Zustand 4 ·
Tailwind 3 (the same palette and gradients as WavePlayer, light and dark) ·
@telegram-apps/sdk-react 2 · react-i18next (ru/en) · hls.js 1.5.20 · MSW 2 · Vitest + RTL.

## Run

```bash
cd apps/cinenest
cp .env.example .env     # VITE_USE_MOCKS empty = "cinema": real gateway auth, mocked /cinema/*
npm ci
npm run dev              # http://localhost:5174/cinenest/ — /api is proxied to api-gateway (:8080)
npm run lint && npm run typecheck && npm test && npm run build
npm run format           # prettier (.prettierrc.json)
```

From the repo root:
- `make cn-dev` starts the dev server on its own.
- `make fe-lint fe-typecheck fe-test fe-build` checks both mini apps.
- `make miniapp-up` starts the whole Telegram dev stack, including CineNest.

### Mock modes (`VITE_USE_MOCKS`)

| Value | auth (`/auth/*`, `/me`) | cinema (`/cinema/*`) |
|---|---|---|
| empty / `cinema` (dev default) | real api-gateway | MSW |
| `all` / `true` | MSW (guest login in a plain browser) | MSW |
| `none` / `false` (production default) | real | real |

The mock catalog has 28 fictional titles (movies and 2-season series) with generated SVG posters.

Mock streams behave like TorrServer:
- A stream warms up for about 4.5 s: first "connecting", then buffering with %, peers, speed and ETA.
- After warm-up it plays a real 60 s HLS clip. The clip is generated by `scripts/gen-mock-hls.sh` into
  `dev-assets/` and served only by the dev server at `/cinenest/__mock-hls/`.
- One title (`TITLES[16]`, exported as `FAILING_TITLE_ID`) always fails with "no peers", so the error UI can be seen.

## Where it lives (ADR 0007)

The app is served under the **`/cinenest/` path prefix on the same origin** as WavePlayer
(Vite `base: '/cinenest/'`, HashRouter inside):
- Dev: WavePlayer's Vite (:5173, the single ngrok URL) proxies `/cinenest` (including HMR websockets) to
  CineNest's Vite on :5174.
- Prod: nginx serves `dist/` at `/cinenest/`.

The `/api` requests go to the same gateway on the same origin, so there is no CORS and no second tunnel.

Telegram entry points:
- In the bot, `/start` and `/help` show two web_app buttons (🎧 WavePlayer, 🎬 CineNest).
- The `/cinema` command (also listed in setMyCommands, RU/EN) opens CineNest.
- The chat menu button stays on WavePlayer, because Telegram allows only one menu button per bot.
- The URL is `MINIAPP_CINENEST_URL` in bot-service; `tools/dev/lib.sh` sets it to `$URL/cinenest/`.

## Screens

- **Catalog.** Search (300 ms debounce), filter All / Movies / Series, "Continue watching" rail with
  progress, and a 3-column poster grid with cursor pagination ("Load more").
- **Watch later.** The user's watchlist (optimistic toggle).
- **Title.** Backdrop, meta, genres, description.
  - Movies: pick a version (2160p/1080p/720p, with sizes).
  - Series: season tabs → episode → quality.
  - "Watch" / "Continue from mm:ss" is the Telegram MainButton, with an in-page button outside Telegram.
- **Player** (fullscreen overlay, lazy chunk with hls.js):
  - `POST /cinema/streams`, then polls the session every 1 s while warming. The warm-up ring shows %,
    peers, speed and ETA. A failed stream offers a retry.
  - hls.js plays the stream; Safari/iOS falls back to native HLS.
  - Resumes from the saved position: positions under 10 s or past 95 % are ignored, and playback starts
    5 s earlier.
  - Position saving: debounced every 5 s, plus a flush on pause, hide, pagehide and close (`keepalive`).
  - Fullscreen uses Telegram `requestFullscreen` (Bot API 8.0+), falling back to the element Fullscreen API
    or `webkitEnterFullscreen`.
  - A "Next episode" button appears at the end of an episode.
  - `DELETE /cinema/streams/{id}` runs on close.
  - The Telegram BackButton works on nested screens.

## API contract

The source of truth is [`docs/api/cinema.openapi.yaml`](../../docs/api/cinema.openapi.yaml)
(OpenAPI 3.1, served by streaming-service behind the gateway from stage 4).

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/v1/cinema/titles?q=&kind=&cursor=&limit=` | catalog page |
| GET | `/api/v1/cinema/titles/{id}` | title with files (seasons/episodes/qualities) |
| PUT/DELETE | `/api/v1/cinema/titles/{id}/watchlist` | watch later |
| GET/PUT | `/api/v1/cinema/titles/{id}/position?fileId=` | watch position |
| GET | `/api/v1/cinema/continue` | continue watching |
| GET | `/api/v1/cinema/watchlist` | watchlist page |
| POST | `/api/v1/cinema/streams` | start a TorrServer stream (warm-up) |
| GET/DELETE | `/api/v1/cinema/streams/{id}` | poll / stop a stream |

## Structure

```
src/
├── app/             App shell (auth splash/error, HashRouter, BackButton), tab bar
├── entities/
│   ├── auth/        token store + initData → JWT session (shared logic copied from WavePlayer)
│   ├── title/       queries (infinite, optimistic watchlist), files (season/quality/resume logic), grid
│   └── player/      useStream (start/poll/stop), warmup view model, positionSaver, hls attach
├── features/        catalog (+continue rail), watchlist, title (+file picker), player (+warm-up overlay)
├── i18n/            ru.json, en.json
├── mocks/           MSW handlers + data (dev only, excluded from production builds)
└── shared/          api client (refresh on 401, timeouts), telegram SDK wrapper, theme, ui, lib
```

Shared code (api client, auth, telegram, theme) is **copied** from WavePlayer instead of being moved to a
shared package. ADR 0007 explains why and when this will change.
